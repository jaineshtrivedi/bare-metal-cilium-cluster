# Operations Runbook

All Kubespray commands use the pinned checkout, Python environment, and generated inventory under `state/`. Set the local kubeconfig before direct Kubernetes operations:

```bash
export KUBECONFIG="$PWD/state/admin.conf"
```

## Reconcile Managed State

Rerun the main playbook after correcting a transient failure or to reconcile configuration drift:

```bash
make cluster
```

Limit a diagnostic rerun to one host when appropriate:

```bash
./scripts/02_deploy_cluster.sh --limit worker2
```

## Add a Worker

Add the host to `WORKER_NODES` in `inventory.env`, regenerate inventory, and run Kubespray's scaling playbook:

```bash
make inventory
cd state/kubespray
../venv/bin/ansible-playbook \
  -i ../inventory/inventory.ini \
  scale.yml \
  --become --limit <new-worker-name>
```

Verify the node and its Cilium agent:

```bash
kubectl get nodes -o wide
kubectl -n kube-system get pods -l k8s-app=cilium -o wide
```

## Add a Control-Plane Node

Add the host to the `[kube_control_plane]`, `[etcd]`, and `[kube_node]` topology generated by the inventory script, with a unique `etcd_member_name`. Use an odd etcd member count and review quorum implications before changing the initial three-member design.

```bash
cd state/kubespray
../venv/bin/ansible-playbook \
  -i ../inventory/inventory.ini \
  scale.yml \
  --become --limit <new-control-plane-name>
```

## Remove a Node

Drain workloads first, then use Kubespray's removal playbook before deleting the host from inventory:

```bash
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data
cd state/kubespray
../venv/bin/ansible-playbook \
  -i ../inventory/inventory.ini \
  remove-node.yml \
  --become --extra-vars "node=<node>" \
  --extra-vars reset_nodes=true
```

Node removal is destructive. Confirm the exact node name and etcd quorum before running it.

## Upgrade Kubernetes

Change `KUBERNETES_VERSION` to a release supported by the pinned Kubespray version, regenerate inventory, and review the diff. Upgrade one minor version at a time:

```bash
make inventory
make upgrade
make validate
```

Upgrade Kubespray separately by changing `KUBESPRAY_VERSION`, recreating `state/kubespray` and `state/venv`, regenerating inventory, and reviewing upstream release notes before running the playbook.

## Test Worker Failure

For planned maintenance:

```bash
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data
kubectl get pods -A -o wide
kubectl uncordon <node>
```

For an unplanned test, power off one worker. The node should become `NotReady`, and controllers should replace replicas where healthy capacity permits.

## Test Control-Plane Failure

Power off one control-plane host or stop kubelet on it. The API VIP should move, API access should recover, and the remaining two etcd members should retain quorum. Recover the host and verify it rejoins before testing another failure.

## Health and Networking Diagnostics

```bash
kubectl get nodes -o wide
kubectl get pods -A -o wide
kubectl -n kube-system get ds cilium
kubectl -n kube-system exec ds/cilium -c cilium-agent -- cilium status --verbose
kubectl -n kube-system exec ds/cilium -c cilium-agent -- cilium-dbg service list
kubectl -n infra-demo get svc,endpoints,endpointslice -o wide
kubectl get ciliuml2announcementpolicy,ciliumloadbalancerippool
```

Inspect policy and flows:

```bash
kubectl -n kube-system exec ds/cilium -c cilium-agent -- cilium endpoint list
kubectl -n kube-system exec ds/cilium -c cilium-agent -- cilium policy get
kubectl -n kube-system port-forward svc/hubble-relay 4245:80
hubble observe --server localhost:4245 --namespace infra-demo
```

On the announcing node, inspect LAN traffic with:

```bash
tcpdump -ni <interface> host <load-balancer-ip> or arp
```

## Reset the Cluster

`make reset` runs Kubespray's destructive reset playbook across every inventoried host. Use it only when intentionally dismantling the cluster; it is not a recovery command.
